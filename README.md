# Трекер в телеграме

Личный бот с отдельными профилями полей: Паша отслеживает режим, развитие,
тренировки и деньги; Света — режим, тренировки, прогулки, учёбу, полезные
занятия, состояние, сладкое и алкоголь. Данные и дашборды изолированы.

Сценарий, под который всё сделано: в течение дня скидывать данные по кусочкам,
а в 23:00 закрывать день одной строкой или голосовым. Ввод терпим к неполноте:
записал утром только подъём, вечером дописал занятия и состояние — запись за дату
обновляется, а не создаётся заново.

## Что внутри

```
cmd/bot            точка входа, graceful shutdown
internal/model     запись дня и реестр полей — единственный источник правды
internal/store     SQLite (modernc.org/sqlite, чистый Go, без cgo)
internal/parse     разбор /d, /m, заметок и свободной речи регулярками
internal/tg        клиент Telegram Bot API
internal/asr       клиент сервиса распознавания речи
internal/llm       клиент Ollama + JSON-схема, сгенерированная из model.Day
internal/report    агрегация, стрики, markdown-выгрузка, флаги
internal/scheduler напоминания по расписанию
internal/bot       хендлеры, голосовой пайплайн, подтверждения
asr/               питоновский сервис faster-whisper + FastAPI
deploy/            unit для systemd и пример env-файла
```

### Почему SQLite, а не JSON-файл

Почти каждая операция здесь — выборка по диапазону дат, обновление одного поля в
существующей строке или агрегат за 30 дней. На JSON-файле всё это превращается в
«прочитать целиком, изменить в памяти, записать целиком», а стрики и недельные
срезы приходится считать руками. SQLite даёт диапазоны, `ON CONFLICT DO UPDATE` и
атомарность из коробки, стоит одну зависимость без cgo (`CGO_ENABLED=0` собирается
статически) и остаётся одним файлом, который копируется с VPS как бэкап:

```sh
sqlite3 /opt/tracker/data/tracker.db ".backup /tmp/tracker-$(date +%F).db"
```

### Поля записи дня описаны один раз

Структура `model.Day` с тегами — источник схемы таблицы, ключей парсера,
JSON-схемы для LLM, текста `/help` и списка незаполненных полей в напоминании.
Добавить поле — значит дописать одну строку в структуру: колонка приедет в базу
миграцией на старте, ключ заработает в `/d`, модель узнает о поле в промпте.

## Команды

| ввод | что делает |
|---|---|
| любой текст | заметка с таймстемпом; `#тег` в начале распарсится в тег |
| голосовое | расшифровка → разбор → подтверждение кнопкой → запись |
| `/d [дата] ключ значение …` | обновить запись дня (upsert по дате) |
| `/m ±сумма категория коммент` | деньги |
| `/s` | статус: сегодня, неделя, капитал, стрики |
| `/w [n]` | выгрузка за n дней markdown-файлом (по умолчанию 7) |
| `/undo` | удалить последнюю заметку или денежную запись |
| `/help` | шпаргалка |

### `/d` — запись дня Паши

```
/d подъем 7:30 отбой 23:40 алго 60 системы 30 трен состояние 8
/d алго нет системы 45 трен нет состояние 6
/d 2026-08-20 подъем 7:30 note сложный день
```

Разделитель — пробел, `=` или `:`, они равнозначны. Тренировку можно писать
голым флагом (`трен`) или явно (`трен нет`); также понимаются `зал`, `бег`,
`улица`, `отдых`. Для занятий число означает минуты, `нет` — не занимался.
Первый аргумент вида `YYYY-MM-DD` — дописать задним числом. `note` забирает
остаток строки.

| ключ | тип | смысл |
|---|---|---|
| `подъем`, `отбой` | ЧЧ:ММ | принимает `7:30`, `7.30`, `0730` |
| `алго` | минуты / нет | алгоритмы |
| `системы` | минуты / нет | системный дизайн |
| `трен` | да/нет | любая тренировка |
| `состояние` | 1–10 | эмоциональное состояние |
| `note` | текст | до конца сообщения |

Для Светы `/help` показывает отдельный набор:

| ключ | тип | смысл |
|---|---|---|
| `подъем`, `отбой` | ЧЧ:ММ | режим |
| `трен`, `прогулка`, `учеба` | да/нет | активность |
| `полезное` | текст | литература, обучающее видео или другое полезное занятие |
| `состояние` | 1–10 | эмоциональное состояние |
| `сладкое`, `алкоголь` | да/нет | питание |

Да/нет понимается как `1/0`, `да/нет`, `+/-`, `y/n`, `true/false`.

Ошибки разбора приходят текстом в чат, а не проглатываются.

### `/m` — деньги

```
/m +250000 зп                 доход
/m -1200 еда обед в кафе      расход; остаток строки — комментарий
/m =180000 накопления         отложено
/m =5000$ холодный кошелёк    валюта суффиксом: ₽ $ € usdt btc
/m =-30000 накопления ремонт  снятие из накоплений
```

Накопленный капитал — сумма всех записей со знаком `=` за всё время, отдельно по
каждой валюте. Норма сбережений в отчёте считается как отложено ÷ доход.
Сумма расхода в дашборде кликабельна: открывается разбивка по категориям и
отдельным операциям.

## Голосовой ввод

```
voice → OpenAI gpt-transcribe → GPT JSON-парсер → подтверждение → запись
                  ↘ при ошибке: ffmpeg → локальный Whisper ↗
```

**Двухуровневый парсинг.** Каждая расшифровка отправляется в LLM API. Регулярки
по ключевым словам (`встал в 7:30`, `алгоритмы 60 минут`, `прогулка`, `учёба`,
`литература`, `сладкое`, `алкоголь`, `состояние 8`) дополняют
ответ модели и остаются бесплатным фолбэком при недоступности API. Уровень
разбора пишется в лог и в базу (`regex`, `llm`, `llm+regex`, `none`):

```sh
sqlite3 /opt/tracker/data/tracker.db "SELECT level, count(*) FROM voice GROUP BY level"
```

**LLM-парсер** — OpenAI-compatible Chat Completions API с JSON-ответом. Провайдер
и модель задаются через `LLM_BASE_URL` и `LLM_MODEL`; без API-ключа остаётся
локальный Ollama-фолбэк. Системный промпт содержит схему из `model.Day`.

**Подтверждение обязательно.** Перед записью бот показывает разобранное с
кнопками «Записать» / «Отменить» / «Показать текст». Последняя показывает сырую
расшифровку — по ней видно, где ASR услышал не то. Ответ на нажатие редактирует
исходное сообщение, а не плодит новые. Причина такая: Whisper по-русски хорош, но
на числах ошибается, а мусор в данных дороже одного нажатия.

**Сырая расшифровка сохраняется рядом с разобранным** в таблице `voice`. По этим
парам потом видно, где модель систематически ошибается:

```sh
sqlite3 /opt/tracker/data/tracker.db "SELECT ts, level, raw, parsed FROM voice ORDER BY id DESC LIMIT 20"
```

**Фолбэк.** Если ASR или LLM API недоступны, бот не молчит и не теряет данные:
голосовое сохраняется заметкой с тегом `#нераспознано` и id файла (сам файл
остаётся на серверах Telegram), в чат приходит объяснение. Ни одно сообщение не
пропадает из-за упавшего сервиса.

## Стрики и напоминания

`/s` показывает профильные серии: для Паши — алгоритмы, системный дизайн и
тренировки; для Светы — учёбу, прогулки, тренировки и полезные занятия.

Незакрытый сегодняшний день стрик не обрывает — иначе он обнулялся бы каждое
утро.

Планировщик — горутина с тикером в часовом поясе из `TZ`:

* **23:00** — напоминание закрыть день с перечислением незаполненных полей;
* **воскресенье 12:40** — недельная выгрузка приходит сама;
Для главного пользователя (Паши):
* **5-го, 10:00** — напоминание записать зарплату;
* **20-го, 10:00** — напоминание записать аванс;
* **1-го, 10:15** — финансовый итог прошлого месяца и AI-анализ расходов.

Дата последнего запуска каждой задачи лежит в базе, поэтому рестарт бота в 23:05
не присылает напоминание второй раз.

## Недельная выгрузка

`/w` собирает профильный markdown-файл. У Паши в нём развитие и финансы, у Светы
— прогулки, учёба, полезные занятия, сладкое и алкоголь. В обоих профилях есть
режим, тренировки, состояние, таблица по дням и заметки.

### Флаги

Пороги — константы в конфиге, переопределяются переменными окружения:

| порог | по умолчанию | env |
|---|---|---|
| разброс подъёма | ≤ 1.5 ч | `MAX_WAKE_SPREAD_H` |
| норма сбережений | ≥ 55 % | `MIN_SAVINGS_RATE` |

## Конфигурация

| переменная | обязательна | по умолчанию |
|---|---|---|
| `BOT_TOKEN` | да | — |
| `OWNER_ID` | да | — |
| `TRACKER_USERS` | для нескольких пользователей | `id:имя:профиль:login:password,…` |
| `TZ` | нет | `UTC` |
| `DATA_PATH` | нет | `./data/tracker.db` |
| `ASR_URL` | нет | `http://127.0.0.1:8081/transcribe` |
| `LLM_API_KEY` | для GPT API | — |
| `LLM_BASE_URL` | нет | `https://api.openai.com/v1` |
| `LLM_MODEL` | нет | `gpt-5.4-mini` |
| `TRANSCRIBE_MODEL` | нет | `gpt-transcribe` |
| `TRANSCRIBE_PROMPT` | нет | словарь трекера и инструкция по числам |
| `OLLAMA_URL` | нет | `http://127.0.0.1:11434` |
| `OLLAMA_MODEL` | нет | `qwen2.5:7b-instruct` |
| `DASHBOARD_ADDR` | нет | — (дашборд выключен) |
| `DASHBOARD_USER` | нет | `tracker` |
| `DASHBOARD_PASSWORD` | при включённом дашборде | — |
| `BACKUP_DIR` | нет | `./data/backups` |
| `DAILY_BACKUP` | нет | `04:00` |
| `INCOME_REMINDER` | нет | `10:00` |
| `MONTHLY_FINANCE` | нет | `10:15` |

`OWNER_ID` — главный пользователь и получатель общего ежедневного бэкапа.
При `TRACKER_USERS` данные каждого ID изолированы в одной базе.

## Дашборд

Дашборд встроен в тот же бинарник и читает ту же SQLite: отдельного фронтенда,
Node.js и второй базы нет. В нём есть периоды 7/30/90/365 дней, ключевые
профильные показатели, состояние по шкале 1–10, стрики и последние дни. Деньги
и детализация расходов выводятся только Паше.

Для запуска за HTTPS-прокси:

```sh
DASHBOARD_ADDR=127.0.0.1:8080
TRACKER_USERS=949465743:Паша:pasha:owner:пароль-1,908821693:Света:sveta:friend:пароль-2
```

Логин и пароль выбирают пользователя и его независимую статистику. HTTP Basic
Auth проверяется самим ботом. Порт стоит оставлять на localhost.

## Бэкапы

В 04:00 бот делает консистентную SQLite-копию через `VACUUM INTO`, хранит
последние 30 дней локально и отправляет файл главному пользователю в Telegram.
Это защищает не только от повреждения базы, но и от потери диска VPS.

## Сборка и тесты

Нужен Go 1.25+.

```sh
make build   # статический бинарник tracker-bot, CGO не нужен
make test
make vet
```

## Деплой на VPS

### 1. Бот

```sh
# на машине разработки
make build
scp tracker-bot root@vps:/opt/tracker/tracker-bot

# на VPS
useradd --system --home /opt/tracker --shell /usr/sbin/nologin tracker
mkdir -p /opt/tracker/data /etc/tracker
chown -R tracker:tracker /opt/tracker
apt install -y ffmpeg          # нужен для конвертации голосовых

cp deploy/bot.env.example /etc/tracker/bot.env
chmod 600 /etc/tracker/bot.env
$EDITOR /etc/tracker/bot.env   # BOT_TOKEN, OWNER_ID, TZ

cp deploy/tracker-bot.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now tracker-bot
journalctl -u tracker-bot -f
```

Обновление: собрать новый бинарник, положить на место, `systemctl restart
tracker-bot`. Схема базы догоняется на старте сама.

### 2. ASR-сервис

```sh
cd asr
docker compose up -d --build
curl 127.0.0.1:8081/health     # первый ответ появится после загрузки весов
```

Модель задаётся в `asr/docker-compose.yml` (`WHISPER_MODEL`). `small` с
`int8` — разумный компромисс для русского на CPU: на VPS с 2 vCPU минута речи
распознаётся за несколько секунд, оперативной памяти нужно около 1.5 ГБ. Если
памяти в обрез, ставьте `base`; если хочется точнее и есть куда — `medium`.

Порт проброшен на `127.0.0.1`: сервис доступен только боту с той же машины.

### 3. Ollama (необязательно)

Нужна только как второй уровень разбора голосовых. Без неё бот работает: если
Ollama недоступна, срабатывает фолбэк, и фраза сохраняется заметкой.

```sh
curl -fsSL https://ollama.com/install.sh | sh
ollama pull qwen2.5:7b-instruct
systemctl enable --now ollama
```

Модели на 7B нужно порядка 6 ГБ памяти. Если столько нет — поставьте
`OLLAMA_MODEL=qwen2.5:3b-instruct` или не поднимайте Ollama вовсе.

## Проверка после раскатки

По порядку, каждый шаг проверяет ровно одно звено:

```sh
systemctl status tracker-bot          # бот жив
journalctl -u tracker-bot -n 20       # в логе строка «подключился bot=…»
curl -s 127.0.0.1:8081/health         # {"ok":true,...} — модель догрузилась
curl -s 127.0.0.1:11434/api/tags      # Ollama видит скачанную модель
ffmpeg -version | head -1             # без него не разберётся ни одно голосовое
```

Дальше в чате с ботом:

1. `/help` — бот отвечает, значит токен и OWNER_ID сошлись;
2. `просто текст` — заметка сохранилась;
3. `/d подъем 7:30 отбой 23:40 алго 60 системы 30 трен состояние 8` — запись дня;
4. `/m -1200 еда обед` — деньги;
5. `/s` — статус со стриками и капиталом;
6. `/w 7` — markdown-файл приходит документом;
7. **голосовое** — приходит карточка с кнопками; нажмите «Показать текст»,
   чтобы увидеть, что именно услышал Whisper;
8. `/undo` — последняя запись удалилась.

Если голосовое отвечает «⚠️ Распознать не удалось» — смотрите причину в тексте
сообщения: она отличает упавший ASR от отсутствующего ffmpeg. Данные при этом
не теряются, фраза лежит в заметках с тегом `#нераспознано`.

Что сработало на голосовом, видно в базе:

```sh
sqlite3 /opt/tracker/data/tracker.db "SELECT ts, level, raw FROM voice ORDER BY id DESC LIMIT 5"
```

## Бэкап

Всё состояние — один файл базы. Пример ежедневного бэкапа:

```sh
echo '0 4 * * * sqlite3 /opt/tracker/data/tracker.db ".backup /var/backups/tracker-$(date +\%F).db"' | crontab -u tracker -
```
