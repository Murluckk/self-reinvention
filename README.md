# Self Rein Tracker

Telegram-бот для ежедневного трекинга небольшой группы людей: у каждого свой
набор показателей, часовой пояс, раздельные данные и личный веб-дашборд.

Что умеет:

- вечерний опрос кнопками по незаполненным полям дня;
- ввод командами и голосовыми сообщениями, правка любого поля голосовой записи
  кнопкой;
- показатели настраиваются каждым пользователем в `/fields`, без правки кода;
- приглашение новых людей одноразовой ссылкой `/invite`;
- статистика, стрики, недельные отчёты и AI-разбор недели;
- наблюдения: какие показатели связаны с эмоциональным состоянием;
- взаимная поддержка по желанию: серии друзей и уведомление «день закрыт»;
- учёт финансов с категориями расходов (включается в `/fields`);
- защищённые паролями дашборды с ограничением попыток входа;
- ежедневные проверенные бэкапы SQLite, алерты о сбоях владельцу;
- OpenAI-совместимый LLM/ASR-пайплайн с локальным Whisper-фолбэком.

## Production

| Компонент | Состояние |
|---|---|
| Telegram-бот | `systemd`-сервис `tracker-bot`, long polling |
| Пользователи | таблица `users` в SQLite, управление командами бота |
| Дашборд | адрес из `DASHBOARD_URL`, HTTPS через Caddy |
| Транскрибация | OpenAI `gpt-transcribe`, фолбэк — локальный `faster-whisper` |
| Разбор голосовых | OpenAI `gpt-5.4-mini`, фолбэк — regex-парсер |
| Хранилище | SQLite `/opt/tracker/data/tracker.db` |
| Бэкапы | ежедневно, с проверкой целостности, локально и в Telegram владельцу |
| Мониторинг | алерты в Telegram из бота и `tracker-alert.service` при падении |

Ключ OpenAI и токен бота лежат только в `/etc/tracker/bot.env` (права `0600`).

## Пользователи и показатели

Источник правды — таблица `users`: Telegram ID, имя, набор показателей,
финансы, часовой пояс, логин дашборда, **хэш** пароля (PBKDF2-SHA256) и флаг
«делиться сериями». Данные всех таблиц разделены по `user_id`.

Каталог возможных показателей — структура `model.Day`. Пользователь выбирает
из него свой набор в `/fields`. Новый вид показателя (например, «медитация»)
добавляется одной строкой в `model.Day`: колонка в SQLite, ключ `/d`, JSON-схема
LLM, кнопки опроса, отчёты и дашборд подхватят его сами.

Стартовые профили (`model.Presets`):

| Профиль | Показатели | Финансы |
|---|---|---|
| `pasha` | подъём, отбой, алгоритмы, системный дизайн, тренировка, состояние | да |
| `sveta` | подъём, отбой, тренировка, прогулка, учёба, полезное, состояние, сладкое, алкоголь | нет |
| `basic` | подъём, отбой, тренировка, состояние | нет |

### Как добавить человека

1. Владелец (`OWNER_ID`) пишет боту `/invite` (или `/invite sveta`).
2. Пересылает ссылку `https://t.me/<бот>?start=inv_…` — одноразовую, на 7 дней.
3. Человек нажимает Start и сразу получает доступ, логин и пароль дашборда.
4. Дальше сам настраивает `/fields` и `/tz`.

Закрыть доступ — `/remove <id>`, список — `/users`. Записи после удаления
остаются в базе.

`TRACKER_USERS` в env нужен только для переноса старой конфигурации: при
первом запуске пользователи оттуда импортируются в базу (пароли — хэшами), а
потом переменную можно удалить.

## Telegram-команды

| Команда | Назначение |
|---|---|
| `/c [вчера\|дата]` | опрос кнопками по незаполненным полям |
| `/d [дата] ключ значение …` | записать или дополнить день одной строкой |
| `/s` | сегодня, неделя, стрики, главное наблюдение |
| `/w [n]` | Markdown-отчёт за `n` дней |
| `/i` | наблюдения за 90 дней |
| `/review` | AI-разбор последней недели |
| `/m ±сумма категория комментарий` | финансы (если включены) |
| `/undo` | удалить последнюю заметку или денежную запись |
| `/fields` | выбрать показатели и включить финансы |
| `/tz [пояс]` | часовой пояс: кнопки городов, `Europe/Berlin` или `+3` |
| `/password` | новый пароль дашборда |
| `/share`, `/friends` | делиться сериями и смотреть серии друзей |
| `/help` | шпаргалка по своим показателям |
| `/invite`, `/users`, `/remove`, `/health` | только для владельца |
| обычный текст | заметка (или ответ на текущий вопрос опроса) |
| голосовое | распознать, показать карточку, записать после подтверждения |

Примеры `/d`:

```text
/d подъем 7:30 отбой 23:40 алго 60 системы 30 трен состояние 8
/d 2026-09-18 подъем 8:10 состояние 7
/d сладкое нет алкоголь нет полезное книга по психологии
```

Текстовые поля (`полезное`, `заметка`) забирают остаток строки — пишите их
последними. Да/нет понимаются как `да/нет`, `1/0`, `+/-`, `y/n`; тренировку
можно записать словами `зал`, `бег`, `улица`, `турник` или `отдых`.

### Вечерний опрос

В 22:00 по поясу пользователя бот присылает не напоминание с синтаксисом, а
первый вопрос с кнопками: да/нет, шкала 1–10, частые длительности, частые
времена подъёма и отбоя. Можно ответить текстом, пропустить вопрос или
закончить. Каждый ответ сразу пишется в базу. Если человек делится сериями,
в напоминании видно, кто из друзей уже закрыл день.

### Финансы

```text
/m +250000 зарплата сентябрь
/m -1200 еда обед в кафе
/m =100000 накопления
/m =5000$ холодный кошелёк
```

`+` — доход, `-` — расход, `=` — перевод в накопления. Первое слово после
суммы — категория, остаток — комментарий. Пользователям с финансами 5-го и
20-го приходит напоминание записать зарплату и аванс, 1-го — итог месяца с
AI-анализом.

## Голосовой ввод

```text
Telegram voice
  → OpenAI gpt-transcribe (фолбэк: ffmpeg + локальный faster-whisper)
  → OpenAI gpt-5.4-mini JSON parser (фолбэк: регулярки)
  → фильтр по показателям пользователя
  → карточка: Записать / Отменить / Исправить / Показать текст
  → запись после подтверждения
```

«Исправить» открывает список полей, после этого значение задаётся кнопкой или текстом.
Сырая транскрипция и разбор сохраняются в таблице `voice`.

## Отчёты, стрики и наблюдения

`/s`, `/w` и дашборд строятся по показателям пользователя. Формат агрегата
зависит от типа поля: время — среднее и разброс (для отбоя 00:30 считается
позже 23:30), длительность — сумма минут и дни, да/нет — «N из M», шкала —
среднее и динамика.

Стрики считаются по «привычкам»: длительностям, полезным да/нет и текстовым
полям. Вредные отметки (`сладкое`, `алкоголь`) серий не дают. Незакрытый
сегодняшний день серию не обрывает.

**Наблюдения** сравнивают среднюю оценку состояния в днях с разными
значениями показателей за 90 дней: тренировка да/нет, занятия были/не были,
подъём раньше/позже медианы. Отбой и вредные отметки сравниваются с
состоянием на следующий день. В выдачу попадает разница не меньше 0.7 балла,
если в каждой группе есть хотя бы 3 дня. Это связи, а не причины.

**AI-разбор недели** приходит в воскресенье вместе с выгрузкой и по
`/review`. В модель уходят только цифры, заметки остаются на сервере.

## Расписание

Каждая задача считается в часовом поясе пользователя. Список задач
пересобирается на каждом тике: новый участник или смена пояса работают без
перезапуска.

| Когда | Действие |
|---|---|
| ежедневно в `DAILY_REMINDER` (22:00) | вечерний опрос |
| воскресенье в `WEEKLY_REPORT` | выгрузка недели и AI-разбор |
| 5-го и 20-го в `INCOME_REMINDER` | напомнить про зарплату и аванс (финансы) |
| 1-го в `MONTHLY_FINANCE` | итог финансов прошлого месяца (финансы) |
| ежедневно в `DAILY_BACKUP` (по `TZ`) | бэкап, проверка, отправка владельцу |

Дата последнего запуска каждой задачи хранится в SQLite, поэтому рестарт не
дублирует уведомления. Упавшая задача повторяется на следующем тике, а
владелец получает алерт.

## Надёжность и мониторинг

- **Алерты в Telegram** владельцу: облачное распознавание ушло на фолбэк,
  LLM не отвечает, упала задача планировщика, паника в обработчике, Telegram
  был недоступен дольше 5 минут, перебор паролей дашборда. Не чаще раза в час
  по одной причине.
- **`/health`**: версия, аптайм, размер и содержимое базы, дата последнего
  бэкапа, последние 10 сбоев.
- **Падение процесса**: если сервис падает 5 раз за 5 минут, systemd
  запускает `tracker-alert.service`, и `deploy/alert.sh` пишет владельцу с
  последними строками журнала.
- **Бэкап** делается через `VACUUM INTO`, затем копия открывается отдельно:
  `PRAGMA integrity_check` и подсчёт записей. В подписи файла видно, что
  внутри. Локально копии хранятся 30 дней.

## Безопасность

- бот молча игнорирует всех, кого нет в `users`; войти можно только по
  одноразовой ссылке;
- пароли дашборда хранятся хэшами PBKDF2-SHA256 (300 000 итераций, соль);
- 10 неудачных входов с одного IP или 20 на один логин за 15 минут — блок на
  15 минут и алерт владельцу; время ответа не выдаёт существующие логины;
- dashboard backend слушает только `127.0.0.1`, HTTPS завершает Caddy;
- друзья видят только факт закрытия дня и длину серий, но не записи;
- финансы видны только тем, у кого они включены;
- бэкап с данными всех пользователей уходит только `OWNER_ID`.

## Конфигурация

Пример — [`deploy/bot.env.example`](deploy/bot.env.example).

```dotenv
BOT_TOKEN=123456:telegram-token
```

флагов, `BACKUP_DIR`) имеет разумные значения по умолчанию и описано в
примере.

## Архитектура

```text
cmd/bot             запуск, расписание, graceful shutdown
internal/model      каталог полей дня, наборы полей, пресеты, пользователь
internal/users      реестр пользователей поверх SQLite, импорт из env
internal/auth       хэши паролей, генерация, ограничение попыток
internal/config     переменные окружения
internal/store      SQLite, миграции, приглашения, бэкапы
internal/parse      /d, /m и regex-разбор речи
internal/asr        локальная и OpenAI-совместимая транскрибация
internal/llm        JSON-схема, LLM-парсер и AI-анализ
internal/bot        хендлеры, опрос, голосовые карточки, аккаунты, алерты
internal/report     статистика, стрики, наблюдения, Markdown-отчёты
internal/dashboard  защищённый read-only веб-интерфейс
internal/scheduler  ежедневные и календарные задачи
internal/tg         Telegram Bot API
asr/                FastAPI + faster-whisper
deploy/             systemd-юниты, alert.sh, deploy.sh, пример env
```

## Разработка

Нужен Go 1.25+.

```sh
make test    # go test ./...
make vet
make build   # бинарник с версией из git describe
```

`internal/bot/flow_test.go` прогоняет сценарии целиком против поддельного
Bot API: приглашение, опрос, `/fields`, друзья, правка голосовой карточки. CI
(`.github/workflows/ci.yml`) на каждый push проверяет gofmt, vet и тесты с
`-race`.

## Деплой

```sh
echo 'DEPLOY_HOST=root@<сервер>' > .deploy.env   # один раз, файл в .gitignore
make deploy
DEPLOY_HOST=root@other make deploy              # разово на другой сервер
```

`deploy/deploy.sh`:

1. отказывается выкатывать незакоммиченный код (`ALLOW_DIRTY=1` — обойти);
2. гоняет gofmt, vet и тесты;
3. собирает статический бинарник под архитектуру сервера с версией из git;
4. обновляет systemd-юниты (старый юнит сохраняет как `.bak-<время>`);
5. останавливает бота и снимает копию базы в `data/predeploy/<время>/`,
   хранит пять последних снимков;
6. подменяет бинарник, сохраняя прежний как `tracker-bot.prev`;
7. ждёт в журнале `подключился`; если бот не поднялся за 20 секунд,
   возвращает прежний бинарник и базу.

Проверка вручную:

```sh
systemctl is-active tracker-bot
curl -fsS http://127.0.0.1:8082/healthz
journalctl -u tracker-bot --since "10 minutes ago" --no-pager
```

Если Telegram отвечает `400: Bad Request: chat not found`, человек ещё не
нажал Start в диалоге с ботом.
